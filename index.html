An alert fires, a human wakes up, and runs the same triage every time — pull the metric, find the trace, read the logs, guess at the cause. Morpheus runs that triage the moment the alert fires, and stops at a human before anything touches production.

Pipeline, in words: an SLI alert fires in vmalert and is routed by Alertmanager to a webhook that triggers the agent — there is no polling. Phase one, the deterministic analyst queries Tempo, Loki and VictoriaMetrics to establish the mechanical failure chain. Phase two, the interpretation agent reads the repository and commit history to explain why it happened. Phase three, a reviewer audits whether the second follows from the first, and routes back to whichever agent failed if it does not. Phase four, the remediation agent searches runbooks by vector similarity and proposes a script. The graph then interrupts and waits for a human to approve, reject or escalate in Slack. Finally a non-LLM gatekeeper checks the script against a whitelist and executes it.

  1. Alert fires

    vmalert → Alertmanager → webhook

    13 PromQL SLI rules across runtime, HTTP and database. Nothing runs until one of them breaks.

  2. Phase 01 The how

    deterministicAnalyst · Tempo · Loki · VictoriaMetrics

    Walks the exemplar from the fired metric to a trace ID, to the span tree, to the log lines around it. Documents the mechanical failure chain and is forbidden from interpreting it.

  3. Phase 02 The why

    interpretationAgent · GitHub tools

    Takes phase one as fact and reads the repository and commits since the alert window. Returns a code-level cause and a process-level one — which change let it through.

  4. Phase 03 Review

    rcaReviewer · structured output, no tools

    Audits whether the “why” actually follows from the “how”. Returns APPROVED or REJECTED with a target node, and the graph routes back to whichever agent overreached.

  5. Phase 04 Remedy

    remediationAgent · ChromaDB RAG

    Searches the runbooks by vector similarity and checks the approved-scripts directory, so it can only ever propose something the executor is actually able to run.

  6. Human gate

    LangGraph interrupt · Slack Block Kit

    State is checkpointed and the graph halts. Approve, reject or escalate in Slack; the decision is patched into state and execution resumes from there.

  7. Resolved

    executionGatekeeper · no LLM

    Deterministic code. Validates the script name against the whitelist and spawns it; anything else pages a human with a severity derived from the alert.

Three decisions

  • Zero polling

    The agent is triggered by an Alertmanager webhook, not a loop. The system costs nothing when nothing is wrong, which is the normal case.

  • A reviewer loop

    A second structured pass audits the causal chain before any fix is proposed. An SRE tool that confidently invents a root cause is worse than no tool.

  • Capped autonomy

    The executor runs three whitelisted scripts and only after a human approves in Slack. The agent proposes; it is never the thing that decides.
